# 校园在线学习平台需求说明书

版本：V1.1

日期：2026-10-26

项目名称：基于 FastAPI 与 Vue 的校园在线学习平台

适用范围：两人软件项目实训；以现有 NovLearn 为开发基础。

## 1. 项目目标与范围

面向校园教学，实现教师管理课程与考核、学生在线学习与交流、管理员审核与维护的完整流程。覆盖实验指导书“在线学习平台”的全部八个基本功能模块，按能独立演示和验收的最小范围实现。

本文描述目标需求，不代表现有功能已经完成或通过测试。复用现有账号、权限、课程、素材、学习记录、考试与通知能力；补齐校园角色、作业、互动、证书及必要管理能力。已有代码满足需求时直接复用，不为统一形式重写。

### 1.1 指导书覆盖关系

| 指导书基本模块 | 本项目落实内容 | 对应章节 |
|---|---|---|
| 用户管理 | 学生与教师注册登录、资料、教师审核、角色分配 | 4.1 |
| 课程管理 | 课程信息、大纲、封面、章节、视频与文档、发布审核 | 4.2 |
| 学习 | 浏览与加入课程、视频学习、文档阅读、作业考试入口 | 4.3 |
| 作业与考试 | 作业发布提交批改、考试设置、客观判分、主观阅卷 | 4.4 |
| 互动交流 | 课程讨论区、文字私信、站内提醒 | 4.5 |
| 学习进度跟踪 | 章节进度、作业状态、考试成绩、教师查看 | 4.6 |
| 证书颁发 | 完成学习并通过考核后领取、查看、打印证书 | 4.7 |
| 系统管理 | 用户与课程审核、备份恢复、基础设置 | 4.8 |

### 1.2 本次不扩展的内容

- 直播、课程推荐、AI 助教、在线支付、学分和排课系统。
- 教务系统对接、校园统一认证、组织架构同步。
- 选课名额、退课审批、先修课、跨学期管理。
- 人脸识别、切屏监测、复杂视频防作弊。
- 群聊、即时聊天、附件私信、消息撤回、多级讨论回复、点赞积分。
- 证书签章、有效期、公开验真与防伪系统。
- Redis、Celery、微服务、云对象存储及 Kubernetes 等额外基础设施。
- 手机专用页面与专项移动端适配；验收以桌面浏览器为主。

既有随机组卷、刷题、Excel 导入、学习路径、培训计划、企业职级岗位等能力，不作为新增开发或本次必须验收内容。保留入口的功能应可用；不纳入校园版的入口可隐藏，不能借隐藏入口绕过后端权限控制。

## 2. 技术方案

### 2.1 技术栈

| 层级 | 目标选择 | 选择依据与边界 |
|---|---|---|
| 运行环境 | 本机已有 Python 3.12；本轮验证解释器为 3.12.14 | 使用独立虚拟环境，复用本机解释器，不升级到 3.15 |
| 后端 | FastAPI + Uvicorn | 复用现有路由、服务和数据校验；无需迁移 Django |
| 数据访问 | SQLAlchemy 2.x 同步模式 + PyMySQL + Alembic | 保留现有同步调用方式；依赖升级到兼容目标 Python 的稳定版本并锁定 |
| 数据库 | 本机已有 MySQL 8.4 LTS，utf8mb4 | 不下载或重装数据库；新建独立校园演示库，应用账号仅访问该库 |
| 前端 | Vue 3 + Element Plus + JavaScript | 优先复用现有页面、API 客户端和路由；不要求改 React、TypeScript 或重新搭建前端工程 |
| 认证 | 现有 JWT 登录与 RBAC，经权限修正后复用 | 增加业务对象归属检查，不仅检查菜单或角色 |
| 文件 | 本地目录存储，受控接口访问 | 复用素材能力；保护作业附件、私有课程资料，不能仅依赖随机文件名 |
| 证书 | HTML 证书页面 + 浏览器打印/另存 PDF | 无需单独部署 PDF 服务或引入证书生成框架 |
| 测试 | 现有 unittest + 真实数据库集成验证 + 页面用例 | 复用累计报告，保留测试环境与日期 |
| 协作与运行 | Git；本地启动脚本与依赖锁定文件 | 不强制容器化，已有部署方式能直接使用则保留 |

现有前端静态资源可继续沿用加载方式；为保证演示不依赖外网，应随交付包提供 Vue、Element Plus 等必要资源，页面不依赖公共 CDN 才能打开。无需仅为此引入 Vite 或额外状态管理库。

### 2.2 版本适配与数据库切换要求

1. 按用户 2026-10-26 的调整，使用本机已有 Python 3.12，不再升级到 3.15；本轮解释器版本为 3.12.14。依赖安装结果和业务验证结果分别记录，不能把导入成功当作整体通过。
2. 在新的虚拟环境中验证 FastAPI、Pydantic、SQLAlchemy、bcrypt、JWT/加密依赖及上传功能；只调整不兼容或必要依赖，不全量重写业务。若出现阻塞，记录具体包与原因，再决定兼容方案。
3. PyMySQL 连接 MySQL 8.4 时支持默认认证方式；按官方文档安装需要的 RSA/加密依赖，不通过降低数据库认证安全性解决连接问题。
4. 复用本机已有 MySQL 8.4，不下载、不重装；先确认现有实例和端口，再新建独立校园库执行 Alembic 迁移并创建演示数据。本次不要求迁移公司业务数据，也不对原 MySQL 5.7 数据目录直接升级或覆盖。
5. 只有在新库完成建表、写入、查询、提交后重新读取及文件访问验证后，才将其作为校园版验收环境。原测试环境与记录保留，不自动改写为新版验证结果。

Python 版本以本机命令输出为准。数据库与认证参考：[MySQL 8.4 手册](https://dev.mysql.com/doc/refman/8.4/en/)、[PyMySQL 安装与认证依赖](https://pymysql.readthedocs.io/en/latest/user/installation.html)。

## 3. 用户角色与权限

### 3.1 角色定义

- **学生**：浏览已发布课程、加入课程、学习、提交作业、考试、参与讨论、与任课教师私信、查看本人进度成绩和证书。
- **教师**：审核通过后管理本人课程、资料、作业、考试；查看本人课程学生及学习情况；批改、回复讨论、收发课程私信。
- **管理员**：审核教师账号与课程，管理用户和角色、处理违规讨论、维护设置、执行备份恢复。

以学生、教师、管理员三个业务角色作为页面与验收口径。可保留原角色表及权限机制，新增或调整角色权限映射；不能只把 author 改成“教师”，就假定其已经具备考试和阅卷权限。

### 3.2 权限矩阵

| 操作 | 学生 | 教师 | 管理员 |
|---|---|---|---|
| 浏览已发布课程简介 | 是 | 是 | 是 |
| 查看完整学习内容 | 已加入课程 | 本人课程；其他课程无默认管理权 | 管理查看 |
| 创建、编辑课程及资料 | 否 | 本人课程 | 管理全部课程 |
| 审核发布课程 | 否 | 仅提交审核 | 是 |
| 发布作业、考试及阅卷 | 否 | 本人课程 | 管理全部课程 |
| 提交作业、考试 | 本人已加入课程 | 无需提供学生作答入口 | 无需提供学生作答入口 |
| 查看学习记录和成绩 | 仅本人 | 本人课程学生 | 管理查看 |
| 删除讨论主题或回复 | 本人内容 | 本人课程内容 | 全部课程内容 |
| 私信 | 本课程任课教师 | 本人课程学生 | 无私信正文浏览入口 |
| 查看与打印证书 | 本人证书 | 本人课程证书记录 | 管理查看 |
| 用户审核、角色分配、系统维护 | 否 | 否 | 是 |

管理员不能通过系统管理页面浏览师生私信正文。所有接口同时校验登录状态、角色和对象范围；修改请求中的用户 ID、课程 ID 或附件 ID 不能扩大权限。

## 4. 功能需求

表内需求均为本期交付范围；“复用”等说明只表达实施来源，不代表已经验收通过。

### 4.1 用户管理（UM）

| 编号 | 需求与验收条件 | 实施来源 |
|---|---|---|
| UM-01 | 学生可使用唯一用户名、姓名、邮箱、密码注册并登录；重复用户名/邮箱明确拒绝，密码不以明文保存。 | 复用并核对 |
| UM-02 | 教师可注册并选择教师身份，账号进入待审核状态；管理员通过后获得教师权限，拒绝时可见原因。待审核账号不能创建课程或考核。 | 补齐 |
| UM-03 | 管理员可查看、搜索用户，审核教师、启用/停用账号、分配三个业务角色；普通注册请求不能自行获取管理员权限。 | 复用并调整 |
| UM-04 | 登录用户可查看和修改本人姓名、邮箱及密码；修改密码需验证原密码，邮箱格式和唯一性在后端验证。个人信息页面不再展示企业职级岗位。 | 复用并补齐 |
| UM-05 | 退出清除客户端登录凭据；受保护接口拒绝无效/过期凭据，停用账号的已有凭据不能继续访问业务接口。 | 复用并验证 |

注册字段不新增学籍认证、手机号验证码或教师工号对接。学生和教师使用同一注册/登录页面即可。

### 4.2 课程管理（CM）

| 编号 | 需求与验收条件 | 实施来源 |
|---|---|---|
| CM-01 | 教师创建和编辑本人课程：名称、简介、课程大纲、封面；列表可按名称搜索并显示教师及发布状态。大纲可直接由章节标题与顺序形成。 | 复用并调整 |
| CM-02 | 教师在本人草稿课程内添加、编辑、删除、排序章节；每章支持文字、视频或文档之一，能够上传封面与资料并预览/下载。 | 复用 |
| CM-03 | 课程按“草稿→待审核→已发布”流转；管理员可通过或驳回并填写原因。仅已发布课程进入学生课程列表；至少有一个有效章节才能提交审核。 | 复用并补齐 |
| CM-04 | 已发布课程的教学内容、题目及考核配置在本期冻结；需要修改时由管理员在无学生加入、无提交记录的情况下退回草稿。已有学习记录的课程只提供归档，不直接删除。 | 调整与约束 |
| CM-05 | 上传限制在前后端一致：图片 JPG/PNG，视频 MP4，文档 PDF/DOCX；默认图片 5MB、文档/作业附件 20MB、视频 200MB。超限或格式错误给出明确提示，文件名不能用于目录穿越。 | 复用并核对 |

PDF 在页面内预览，DOCX 提供下载；不要求在线编辑或将 Office 文档转换为网页。课程分类沿用已有基础能力即可，不扩展复杂标签体系。

### 4.3 在线学习（LM）

| 编号 | 需求与验收条件 | 实施来源 |
|---|---|---|
| LM-01 | 学生浏览已发布课程，按名称搜索、查看简介与大纲，点击“加入学习”进入我的课程；同一学生加入同一课程只产生一条成员关系。 | 列表复用；加入操作补齐 |
| LM-02 | 已加入学生可从我的课程进入章节，播放视频、阅读文字、预览 PDF 或下载文档。未加入者只能查看简介，不能直接通过接口取得受限资料。 | 复用并调整 |
| LM-03 | 视频保存播放位置，重新进入时可以继续播放；视频播放结束可标记该章完成；文字和文档由学生点击“完成本章”。不增加人脸识别或复杂防快进要求。 | 复用并简化 |
| LM-04 | 章节详情可跳转本课程讨论、作业和考试；归档课程停止新加入与新提交，已加入学生仍可查看历史学习内容、成绩与证书。 | 补齐关联入口 |

学生自主加入只做一次点击，不做名额、审批或退课。可在现有 CourseAssignment 中用用户类型的记录表达成员关系，无需同时新建重复的选课业务；教师安排课程可继续复用同一关系。

### 4.4 作业与考试（AS / EX）

#### 4.4.1 作业

| 编号 | 需求与验收条件 | 实施来源 |
|---|---|---|
| AS-01 | 教师为本人课程创建作业，填写标题、文字要求、截止时间、满分、评分说明及是否为必交作业；发布后学生可见。 | 新增 |
| AS-02 | 已加入学生在截止时间前提交文字、一个附件或二者；至少有一项内容。截止前且尚未批改可修改提交，只保留一份当前提交，不实现版本历史。 | 新增 |
| AS-03 | 教师查看本人课程提交列表、文字与附件，录入 0～满分之间的分数及评语；学生仅可查看自己的提交和批改结果。批改后刷新并重新登录仍保留成绩。 | 新增 |
| AS-04 | 已截止不能新交或修改；未批改显示“待批改”，不能当作 0 分。发布后存在提交的作业不能删除或修改满分、必交标识。 | 新增 |

作业采用人工批改，不另做题库式作业引擎、自动查重或多附件管理。作业评分说明用文字表达，不实现复杂评分维度配置。

#### 4.4.2 考试

| 编号 | 需求与验收条件 | 实施来源 |
|---|---|---|
| EX-01 | 教师维护本人题库，支持单选、多选、判断、简答四类；题干、选项、正确答案/参考答案、分值可录入。选择题至少两个有效选项，答案必须与选项匹配。 | 复用并核对 |
| EX-02 | 教师从本人题库手动组卷，考试绑定本人课程，设置标题、题目与分值、开放起止时间、答题时长、及格百分比、最多尝试次数和评分说明。 | 复用并调整 |
| EX-03 | 已加入学生在开放时间内开始考试；后端验证成员身份、考试时间和次数，截止点为“开考时间+答题时长”与关闭时间的较早者。前端显示倒计时并在到期时提交，不能仅依赖客户端时间。 | 复用并修复 |
| EX-04 | 客观题自动判分：单选/判断完全正确得分，多选与正确选项集合完全一致得分；简答题由教师人工批改。作答中不向学生返回正确答案和解析。 | 复用并核对 |
| EX-05 | 满分取本次考试固定题目分值总和，漏答计 0 分、不减少满分；重复题目答案与试卷外题目在后端拒绝；同一考试记录重复提交不得重复计分或占用额外次数。 | 必修复与验证 |
| EX-06 | 含未批主观题时状态为“待批改”，不生成最终通过结论；教师可从页面进入待批记录，填写各题分数与评语，全部题目批改后才产生最终成绩和通过结果。 | 接口复用；页面与逻辑补齐 |
| EX-07 | 学生查看本人已提交记录、客观得分、待批状态及最终成绩；教师查看本人课程考试的提交人数、待批记录和最终成绩列表。最终成绩按“得分/固定满分×100”与及格百分比比较。 | 复用并修复 |
| EX-08 | 开考时保存题目、题型、答案规则和分值快照，后续题库修改不改变已经开始的考试记录；试卷发布后冻结题目与分值，存在作答时不能删除试卷。 | 补齐/核实 |

不新增随机组卷、复杂统计图表、错题推荐或填空题判分规则。既有功能无需扩展；考试先保证四种题型和人工阅卷完整可用。

考试页面刷新后保留当前尝试与服务器截止时间，不能刷新获得额外时长或次数。无需服务器定时自动收卷服务：到期后禁止继续答题，提交/再次访问时按截止规则结束；未交卷不得获得通过或证书资格。不要求断网自动保存每次按键。

### 4.5 互动交流（CO / PM）

| 编号 | 需求与验收条件 | 实施来源 |
|---|---|---|
| CO-01 | 每门课程提供独立讨论区，已加入学生与任课教师可发布文字主题；显示标题、内容、作者与时间，按时间分页。 | 新增 |
| CO-02 | 主题下可发表一级文字回复，学生可提问、分享心得，任课教师可答疑；不做多级楼中楼。 | 新增 |
| CO-03 | 作者可删除本人主题/回复，任课教师可删除本人课程违规内容，管理员可管理全部课程讨论；删除主题后其回复不再可见。 | 新增 |
| PM-01 | 同一课程的学生与任课教师可互发纯文字私信，按对方查看往来记录，显示发送时间与已读/未读；不开放任意用户搜索和陌生人私信。 | 新增 |
| PM-02 | 私信正文仅发送者与接收者可访问；普通课程成员不能通过猜测消息 ID 读取内容，页面按打开或刷新获取新消息，无需 WebSocket。 | 新增 |
| CO-04 | 作业批改完成、最终考试成绩发布、讨论主题收到他人回复、收到私信时提供站内未读提醒；刷新或打开对应页面可更新未读状态。通知不包含私信正文。 | 通知基础复用 |

不做讨论图片、文件、表情、点赞、群聊和消息撤回。讨论只需主题列表与详情两个视图，私信可用联系人列表与消息面板完成。

### 4.6 学习进度跟踪（PR）

| 编号 | 需求与验收条件 | 实施来源 |
|---|---|---|
| PR-01 | 学生查看每门已加入课程的已完成章节数、总章节数和进度百分比；整课进度为已完成章节数/有效章节总数，视频播放位置单独保存。重复完成同一章不累计次数。 | 复用并修复 |

## 5. 核心业务规则

1. **课程归属**：每门课程只有一名任课教师，默认创建者；不实现助教、多教师协同或课程转让。
2. **课程成员**：学生自主加入已发布课程；成员关系唯一，所有学习、作业、考试、讨论均以课程范围校验权限。
3. **发布前准备**：教师在草稿阶段准备章节、作业、试卷和证书规则，相关内容随课程发布对学生开放；发布后只处理提交、评分和互动，不编辑教学结构。
4. **时间**：界面使用北京时间（Asia/Shanghai），服务端统一比较时间；截止边界为服务器时间达到截止时间即结束，不使用客户端时间判断资格。
5. **评分**：成绩不得小于 0 或大于对应满分；未批改与 0 分分别保存、展示。主观题得 0 分仍可表示“已批改”，不能用“是否得分”代替批改状态。
6. **最终成绩**：部分批改保持待批状态；重复保存同一批改不重复加分。提交数据库事务后重新加载，答案分数、评语、总分和状态一致。
7. **证书条件**：学习完成、必交作业批改完成、指定考试最终及格三项同时满足，才允许领取。作业不额外设置及格线，避免扩展规则引擎。
8. **重复请求**：加入课程、完成章节、交卷、发完成通知、领取证书均应避免重复产生业务结果；唯一约束或事务保证不能只放在按钮禁用逻辑中。
9. **资源访问**：私信、作业附件、成绩和受限课程资源通过后端鉴权；学生不能读取其他学生提交或考试正确答案，资料 URL 不能绕过身份和课程范围。
10. **内容输入**：讨论、私信、作业文字按纯文本展示；不直接执行或渲染用户提交的 HTML/脚本。

## 8. 非功能与验收要求

### 8.1 基本质量要求

- **可运行**：按 README 在干净环境完成依赖安装、数据库迁移、演示数据初始化及启动；不依赖作者机器绝对路径。
- **访问安全**：密码摘要存储、后端权限检查、上传校验、资源鉴权有效；密钥和真实账号凭据通过环境配置提供。
- **数据一致性**：作业、成绩、学习记录和证书保存后刷新、重新登录、重启应用仍能读取；关键步骤使用真实 MySQL 8.4 验证。
- **易用性**：错误提示能说明原因，列表有分页；显示课程名称而非只有 UUID，待审核、待批改、零分等状态清楚区分。
- **演示规模**：至少准备 1 名管理员、1 名教师、2 名学生、1 门不少于 2 章的课程、1 份作业及 1 场含客观题和简答题的考试。
- **性能边界**：以本地/局域网小组演示为目标，不要求压测平台或高并发承诺；普通列表操作不应长时间无响应，视频上传不一次性读入全部文件到内存。
