# 演示数据与操作说明

日期：2026-10-30。演示对象全部为虚构账号和课程，与随机 QA 数据分开。网站：[本地校园平台](http://127.0.0.1:20081/)。

## 1. 准备

在仓库根目录启动服务，再初始化一次：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-local.ps1
.\.venv\Scripts\python.exe scripts/setup_demo.py
```

脚本只操作项目独立的 `127.0.0.1:3309/campus_learning`，不清空已有数据，不重置已有账号。重复执行会复用原演示集并保留学习、作业、考试和证书结果。已有保留用户名却没有本地清单时，会拒绝覆盖；数据库或演示集被手动删除后，也应先核对清单与数据库，不能盲目重复初始化。

本地账号、随机生成密码及课程 ID 在 `.runtime/demo.json`，用编辑器查看。不要把该文件放入公开源码、截图或报告。脚本不在控制台打印密码。账号如下，四个账号密码分别生成：

| 身份 | 用户名 | 初始状态 |
|---|---|---|
| 管理员 | `campus_demo_admin` | 平台管理 |
| 教师陈老师 | `campus_demo_teacher` | 已审核，通过本人课程管理 |
| 学生林同学 | `campus_demo_student1` | 已加入演示课程，未开始学习 |
| 学生周同学 | `campus_demo_student2` | 已加入同一课程，供对照 |

课程“校园演示：计算机网络入门”包含两个文字章节、一份必交学习小结、一场 30 分钟/最多 3 次的五题考试（单选、多选、判断、两道简答）、欢迎讨论主题，以及指定结课考试的证书配置。作业和考试在初始化后 30 天内开放，具体截止见本地清单和网页；重复初始化不延长已发布考核时间。

演示集从未学习、未提交开始，成绩与证书通过下面实际操作产生。基础演示不依赖外部视频或文档下载；素材上传、PDF/DOCX 阅读可另用自己的虚构资料，在教师新建草稿中展示。

## 2. 推荐演示顺序

1. 用教师登录，打开本人演示课程，展示两章、作业要求、五题试卷及证书规则。该课已发布，修改教学内容的入口受限。
2. 教师另建一门草稿课程，添加两章文字，把第二章顺序设为 5、第一章设为 10；保存并刷新，展示排序。编辑章节改为文档类型，点击素材刷新，确认正常加载。需要演示审核时，再用管理员通过该新草稿的审核。
3. 切换学生一进入已加入课程，完成第一章，展示 50%；再完成第二章，展示 100%。说明章节完成与考试通过、证书领取分别判断。
4. 学生一提交“学习小结”。可先修改一次，再由教师批改为 85 分并填写评语。学生重新登录确认结果保留，已批后不能改交。
5. 学生一开始结课考试，填写客观题和第一道简答，第二道简答留空。可先保存并刷新，确认当前尝试与剩余时间保留，再交卷。
6. 教师从课程“答卷与阅卷”进入详情。空白简答已自动 0 分，没有人工评分框；非空简答仍待批，整卷没有最终通过结论。教师为非空题评分后保存，最终成绩发布。
7. 若客观题全部正确、非空简答得 20 分，则总分为 80/100，达到 60% 及格要求。学生返回课程，领取证书、重开并打印；重复领取仍是同一份。若未及格，可在次数和开放时间内再次尝试。
8. 学生回复欢迎讨论主题，教师回复；学生与任课教师互发文字私信。查看通知未读与跳转，说明管理员没有师生私信正文入口。
9. 教师打开学生进度表，对比学生一的完成、作业、最终成绩与学生二的未学习状态。
10. 最后用管理员展示用户/课程审核与基础设置。归档会停止新写入，建议只对单独新建的演示草稿/测试课程展示，避免影响主课程后续继续演示。

同一账号再次登录会使原会话失效，三种身份请在不同浏览器窗口使用不同账号，或依次退出切换。不要同时使用同一个账号跑回归脚本和操作网页。
